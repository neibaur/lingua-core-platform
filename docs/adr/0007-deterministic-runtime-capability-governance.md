# ADR 0007: Deterministic Runtime Capability Governance

## Status

Accepted

## Context

The query runtime now declares and validates its own capability surface through
explicit immutable manifests. Structural certification, compatibility evaluation,
governance reporting, audit snapshots, operational rollup, provenance attestation,
and closure envelopes are all implemented under
`src/core/tokenizers/search/runtime-capabilities/`.

The runtime capability governance layer is not a plugin host, capability
registry, or ambient discovery mechanism. It is a deterministic infrastructure
layer that describes completed runtime capability structures in replay-safe,
serialization-safe, and recursively frozen artifacts — without executing
queries, mutating shared state, persisting records, or coupling to any external
orchestration system.

## Decision

Formalize deterministic runtime capability governance under
`src/core/tokenizers/search/runtime-capabilities/` as the repository law for
runtime capability certification artifacts.

Runtime capability governance artifacts are synchronous, in-memory,
dependency-free, framework-agnostic, persistence-agnostic,
canonical-serialization-safe, and immutable. They describe completed runtime
capability structures. They do not execute queries, discover capabilities from
the environment, mutate runtime state, persist records, emit telemetry, or
delegate to plugin systems.

## Governance Layer Stack

The governance pipeline is an explicit, layered composition sequence. Each
layer derives state from exactly one field of the immediately preceding layer.
No layer may inspect sub-structure of any layer other than its direct
predecessor.

```
manifest
→ validation
→ certification
→ aggregation
→ introspection
→ governance report
→ audit snapshot
→ operational governance manifest
→ provenance / replay attestation
→ governance closure
```

The terminal artifact is `RuntimeGovernanceClosure`. It exposes `closureStatus`,
derived exclusively from `provenance.attestationStatus`. The closure is the
outermost governance boundary before ADR archival or cross-system handoff.

## Layer Derivation Rules

Each layer follows these invariants:

- `RuntimeCapabilityGovernanceReport.reportStatus` derives from
  `introspectionEnvelope.certificationSummary.globalStatus`.
- `RuntimeCapabilityCertificationAuditSnapshot.auditStatus` derives from
  `governanceReport.reportStatus`.
- `RuntimeOperationalGovernanceManifest.governanceStatus` derives from whether
  every `auditSnapshot.auditStatus` is `"passed"`. An empty snapshot array
  passes vacuously — it represents a clean rollup boundary with no recorded
  failures.
- `RuntimeGovernanceProvenance.attestationStatus` derives from
  `operationalManifest.governanceStatus`.
- `RuntimeGovernanceClosure.closureStatus` derives from
  `provenance.attestationStatus`.

Lower-layer reach-through or recomputation is prohibited. A layer may not
traverse the sub-structure of any artifact below its direct predecessor.

## Capability Manifests

`RuntimeCapabilityManifest` is an explicit, immutable declaration of the
capabilities present in a runtime build. Manifests are caller-composed from
declared `RuntimeCapabilityDeclaration` entries. They are not generated by
reflection, plugin loading, environment scanning, or ambient discovery.

Certification compares a manifest against a baseline using structural matching.
The result is a `RuntimeCapabilityCertificationArtifact` with status
`"certified"` or `"rejected"`, and zero or more `structuralMismatches`.
Certification is deterministic: the same manifest and baseline always produce
the same result.

## Caller-Supplied Identifiers

All governance artifact identifiers — `manifestId`, `reportId`, `snapshotId`,
`manifestId`, `provenanceId`, `closureId` — are caller-supplied string values.
Composition functions never generate identifiers from UUIDs, timestamps,
hashing, randomness, crypto APIs, or process state.

## Timestamp Sentinel

`evaluationTimestamp: null` is the replay-safe timestamp sentinel used across
all governance artifacts. No governance composition function calls `Date.now()`,
`performance.now()`, or any clock API. The null sentinel is a typed field
constraint, not a missing value.

## Immutable Artifact Contracts

All externally exposed governance artifacts must be recursively frozen before
return using `deepFreezeStructure(...)`. The immutability contract applies at
every layer:

- Composition functions return frozen artifacts.
- Nested arrays and nested artifact objects are frozen.
- Consumers must treat governance artifacts as values, not mutable records.
- Mutation after composition is not part of the governance model.

TypeScript `readonly` and `ReadonlyArray` contracts enforce the same boundary
at compile time.

## Deterministic Ordering

`RuntimeOperationalGovernanceManifest.auditSnapshots` is sorted by `snapshotId`
using explicit binary string comparison (`a < b ? -1 : a > b ? 1 : 0`). Input
arrays are cloned before sorting; the caller's array is never mutated. Sorting
must not depend on locale collation, insertion order, runtime process state, or
implementation-defined enumeration behavior.

## Canonical Serialization

`stableJsonStringify` is the canonical serialization boundary for governance
artifacts. Governance artifacts are JSON roundtrip-safe: values must remain
representable through JSON primitives, arrays, and plain objects without loss
of deterministic governance meaning.

## Schema Version Convention

Phase 9 governance artifacts use domain-specific schema version literals in
the form:

```
lingua-core-platform:<artifact>@phase9
```

This is not a semver value. Examples:

- `"lingua-core-platform:runtime-capability-governance-report@phase9"`
- `"lingua-core-platform:runtime-capability-certification-audit-snapshot@phase9"`
- `"lingua-core-platform:runtime-operational-governance-manifest@phase9"`
- `"lingua-core-platform:runtime-governance-provenance@phase9"`
- `"lingua-core-platform:runtime-governance-closure@phase9"`

Prior Phase 9 artifacts (manifest through introspection envelope, introduced
before the domain-literal convention was formalized) use `"1.0.0"`. A
normalization slice to backfill those artifacts to the domain-literal form is
planned and will be tracked as a separate architectural change.

## Consequences

- Runtime capability governance becomes a formal architecture boundary rather
  than an ad-hoc validation helper or test utility.
- Future runtime capability work must consume immutable governance artifacts
  rather than observe mutable runtime state or inspect capability structures
  directly.
- Expansion of the governance layer stack — new artifact types, additional
  certification strategies, or extended snapshot metadata — must preserve
  deterministic ordering, canonical serialization, single-layer derivation,
  immutable contracts, and caller-supplied identifiers.
- The schemaVersion domain-literal convention applies to all governance
  artifacts introduced at or after the closure slice.
- Cross-system consumers of governance closure artifacts receive a terminal,
  replay-safe, recursively frozen record that fully represents the certification
  posture of a runtime capability surface without requiring access to lower
  governance layers.

## Alternatives Considered

**Plugin-based capability registry**: Rejected. Runtime discovery from plugin
registries is environment-sensitive, non-deterministic, and incompatible with
replay-safe artifact composition.

**Async governance pipeline**: Rejected. Async orchestration introduces ordering
ambiguity, error surface, and external dependencies incompatible with the
deterministic in-memory model required by the governance contract.

**Semver schema versions**: Rejected. Semver implies release management
semantics that do not apply to internal governance artifact schemas. Domain
literals make the artifact provenance and phase explicit without implying a
public versioning contract.

**Mutable governance state machines**: Rejected. Mutable shared state cannot
produce recursively frozen, JSON roundtrip-safe, replay-identical artifacts.
The static composition model is both simpler and stricter.

## Non-Goals

This decision does not introduce rendering, markdown report generation, CLI
output, persistence, telemetry, async orchestration, plugin registries, runtime
capability discovery, distributed governance execution, optimizer-driven
behavior, DI containers, workflow engines, AI orchestration runtimes, heuristic
optimizers, mutable singleton state, hidden caches, or event systems.
